一、个人通俗解释

类比：普通大模型像一位学识渊博但只能"动嘴"的私人助理，你问一句他答一句；Agent 则是给这位顾问配上了手脚、工具和待办清单——他会自己拆解任务、翻资料、找工具、动手干活，看结果不对再次修改，直到完成最终要求。

严格定义：Agent（智能体）是以大模型（LLM）为"大脑"，能够自主的记住信息、拆解目标、规划步骤、调用外部工具并根据反馈循环迭代的系统。关键是"自主决定下一步做什么"，而不是被动一问一答。不需要一步步指挥，只需要说清最终要做什么，它就能自己搞定全流程。

二、核心机制

  1. 接收目标：输入不再是单个问题，而是一个需要多步完成的任务（如"修复这个 bug 并提交"）。
  2. 规划与思考：模型把大任务拆成小步骤。典型循环是 ReAct 模式：思考 → 行动 → 观察结果 → 再思考。
  3. 工具调用（Tool Use）：模型输出结构化的"调用请求"（如搜索网页、执行代码、读写文件），环境执行后把结果喂回上下文。没有工具，模型只能靠记忆瞎猜外部信息。
  4. 记忆：短期记忆靠上下文窗口（Context）装下当前进展；长期记忆可借助向量数据库把历史信息存起来、按需检索。
  5. 循环直到完成：每轮观察反馈后决定"继续做、换方法，还是任务已完成"。没有这个闭环的话，一次回答错了就全盘皆输，无法自我纠正。

它解决的前置问题：单次 LLM 调用只会"一问一答"，无法处理多步、需要外部信息和自我纠错的复杂任务。

三、真实应用场景

  • GitHub Copilot coding agent：场景 → 用户提交一个 issue 后它自主读代码、改代码、跑测试 → 效果：把"提需求"到"收到 PR"变成半自动流程。
  • OpenAI Deep Research：场景 → 面对一个研究问题，agent 自动拆解为多轮检索与阅读 → 效果：产出带引用来源的长篇研究报告。
  • Anthropic Claude Code：场景 → 开发者用自然语言描述改动，agent 自主读写代码库、运行命令 → 效果：完成跨文件的工程任务而不只是补全代码。
  • 电商客服 Agent：场景 → 用户说"我要退货"，agent 自主调用订单、物流、退款接口完成全流程 → 效果：无需人工逐个系统查询。

四、易混淆边界

  • Agent vs 聊天机器人（Chatbot）：区别点 → 有无自主规划与工具循环；适用情况 → 一问一答用 Chatbot，多步任务用 Agent；口诀："Chatbot 答话，Agent 干活。"
  • Agent vs 工作流（Workflow）：区别点 → Workflow 由开发者预先写死每一步，Agent 由模型自己决定步骤；适用情况 → 流程固定、要求可控用 Workflow，路径不确定用 Agent；口诀："Workflow 走剧本，Agent 临场发挥。"
  • Agent vs 工具调用：区别点 → 工具调用是单次动作，Agent 是围绕目标的完整决策循环；适用情况 → 单次查询直接调工具即可，需多轮配合才是 Agent；口诀："工具是招式，Agent 是会连招的武者。"

五、权威参考链接

  1. ReAct: Synergizing Reasoning and Acting in Language Models（arXiv 2210.03629）——提出"思考-行动-观察"循环的开山论文，想理解 Agent 核心循环时读。
  2. Lilian Weng: LLM Powered Autonomous Agents——Agent 领域最著名的综述博客（规划/记忆/工具三件套），建立整体认知框架时看。
  3. Anthropic: Building Effective Agents——工业界视角讲何时该用 Workflow、何时该用 Agent，做工程选型时读。
  4. Toolformer（arXiv 2302.04761）——让模型自己学会何时调用工具的早期论文，了解工具调用由来时看。

六、自测思考题

1. 为什么"单次大模型调用"不够，需要 Agent？

参考要点：复杂任务需多步、需外部实时信息、需根据反馈自我纠正；单次调用没有循环与工具，做不到这三点。

2. 描述 ReAct 循环的三个基本动作。

参考要点：思考（决定下一步）→ 行动（调用工具）→ 观察（接收结果并加入上下文），循环往复直到达成目标。

3. Workflow 和 Agent 的本质区别是什么？各自适合什么场景？

参考要点：控制权归属不同——Workflow 的步骤由开发者写死（可控、可预测），Agent 的步骤由模型临场决定（灵活、适合开放任务）。对可靠性要求高的固定流程用 Workflow。

4. Agent 的"记忆"分哪两类？分别靠什么实现？

参考要点：短期记忆靠上下文窗口保存当前会话内容；长期记忆靠外部存储（如向量数据库）持久化并按需检索。
