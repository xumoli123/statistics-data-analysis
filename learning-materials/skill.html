一、个人通俗解释

类比：Skill 就像给 AI 配的一本标准指导说明书——平时整整齐齐码在抽屉里，AI 只记得每本书的名字和一句话简介；一旦接到匹配的任务，才把对应那本抽出来翻开，照着里面的流程、模板和顺序干活。

严格定义：Skill 是一个以 SKILL.md 说明文件（可附带脚本、模板等资源）为核心的文件夹包，通过名称和描述被 Agent 感知、在任务匹配时按需加载，用来教会 Agent 一项具体、可复用的正确标准工作流程。

二、核心机制

  1. 文件夹即技能：每个技能是一个目录，核心是带 frontmatter（名称 + 描述）的 SKILL.md，可附带脚本与模板资源。
  2. 轻量感知：系统启动时 Agent 只"看到"每个技能的名称和一句话描述，几乎不占用上下文窗口——这是它能同时挂载数十个技能的前提。
  3. 按需加载（Progressive Disclosure，渐进式披露）：当任务与描述匹配时，完整的 SKILL.md 内容才被读入上下文；不像系统提示那样常驻。
  4. 资源按需读取：技能内附带的脚本、参考文档只在需要时执行或读取，进一步节省窗口。
  5. 组合扩展：复杂技能可以在说明中引用其他技能，形成流程串联。

它解决的前置问题：若把所有领域的操作流程都塞进系统提示，既会撑爆上下文窗口，又会互相干扰降低准确率；Skill 让知识"用时才取"。

三、真实应用场景

  • Anthropic Agent Skills 官方文档技能：场景 → Claude 预置 docx / pptx / xlsx 等技能 → 需要处理对应 Office 文件时自动加载 → 效果：按官方规范生成文件而非凭记忆瞎猜格式。
  • 团队自定义技能：场景 → 公司把周报格式、代码评审清单写成 SKILL.md → 团队所有 Agent 会话共享同一套做法 → 效果：输出风格统一、可版本化管理。
  • Claude Code 中的技能：场景 → 开发者把"发布流程"做成技能，对话中以斜杠命令触发 → 效果：多步运维操作一条命令复现。
  • 个人工作流沉淀：场景 → 用户让 AI 把本次多步任务的成功做法存为技能 → 下次一句话复用 → 效果：经验从"聊天记录"变成"可执行资产"。

四、易混淆边界

  • Skill vs 工具（Tool）：区别点 → 工具是单个可调用的接口（如"搜索网页"），技能是打包的流程知识（知道何时、按什么顺序用哪些工具）；适用情况 → 加能力用工具，传方法用技能；口诀："工具是零件，技能是装配说明书。"
  • Skill vs MCP：区别点 → MCP 负责把 Agent 连到外部数据与服务（连接层），Skill 负责教会 Agent 做事的方法（知识层）；适用情况 → 两者常配合：MCP 提供接口，技能提供用法；口诀："MCP 通水管，Skill 交手艺。"
  • Skill vs 系统提示（System Prompt）：区别点 → 系统提示常驻且全量加载，技能按需加载；适用情况 → 全局规则放系统提示，特定任务流程做成技能；口诀："宪法常在墙上，手册用时才翻。"

六、自测思考题

1. Skill 为什么采用"按需加载"而不是全部写进系统提示？

参考要点：全量加载会占用大量上下文窗口且多领域知识互相干扰；按需加载让窗口保持干净，同时支持挂载更多技能。

2. 一个最小可用的 Skill 文件夹包含什么？

参考要点：一个目录 + 一个带 frontmatter（name、description）的 SKILL.md；描述写得越准确，Agent 触发越可靠；可选附带脚本与模板。

3. "渐进式披露"的三个层级分别是什么？

参考要点：第一级只暴露名称+描述（常驻、极轻）；第二级任务匹配时加载 SKILL.md 正文；第三级执行中按需读取附带资源文件。

4. 如果要"让 AI 每次都按公司模板写周报"，Skill、工具、MCP 各扮演什么角色？

参考要点：技能承载周报的结构化流程与模板知识；工具/MCP 提供读取数据、写入文档的接口能力；技能指导如何组合这些工具完成全流程。
